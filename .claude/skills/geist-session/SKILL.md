# Geist-сесія: один етап трекера

## Старт
1. Прочитай `docs/geist-migration.md`: шапку (конвенції прогону) + перший етап зі статусом 🔲.
2. Працюй ТІЛЬКИ в межах цього етапу; одна сесія = один етап.
3. Примітка-blockquote під заголовком етапу визначає пакетування
   (стаби одним комітом, спільний CSS одним проходом, _RefEntityPage одним аудитом,
   великий TSX без власного CSS — тріаж оркестратором) — виконуй її.
4. `docs/geist/` сам НЕ читай — це робота migrator-а. Для тріажу достатньо
   фрагментів коду в його звіті; сторінку перечитуй лише коли фрагментів мало.

## Маршрутизація кроків (модельна матриця)

| Крок | Хто | Модель |
|---|---|---|
| Redirect-стаб | сам: один Read, підтвердити redirect-only | — |
| Аудит сторінки | Agent geist-migrator | sonnet (дефолт агента) |
| Великий TSX без власного CSS | сам (inline-стилі + JSX) | — |
| Тріаж знахідок | сам | — |
| Повністю механічний список правок | Agent geist-fixer + параметр `model: "haiku"` | haiku |
| Змішаний/сумнівний список | Agent geist-fixer | sonnet (дефолт агента) |
| Структурне (ModalShell, layout, DOM) | сам | — |
| Перевірка після правок | сам: `git diff` проти списку + `npx tsc --noEmit` | — |

«Повністю механічний» = migrator позначив УСІ передані пункти `механічне`
(підсумок звіту «список повністю механічний: так»). Хоч один структурний
або сумнівний пункт у передачі → sonnet.

## Гарди haiku-fixer
Після haiku-прогону обов'язково: (1) `git diff` — кожен пункт списку застосовано,
жодного зміненого рядка поза списком; (2) `npx tsc --noEmit`.
Будь-який провал → `git checkout -- <файли fixer-а>` (повний відкат) і перезапуск
ТОГО САМОГО списку на sonnet. Haiku-diff вручну не латати.

## Незмінні правила
- `npx tsc --noEmit`, НІКОЛИ не `npm run build` (dev може бути відкритий).
- 1 коміт = 1 сторінка; стаби етапу — одним комітом; push у main.
- БЕЗ Playwright і скріншотів — візуальну перевірку робить користувач на Vercel.
- Рядок трекера оновлює migrator; для сторінок без migrator-а (стаби,
  оркестраторський аудит) — оновлюєш сам у тому ж форматі (статус/дата/знахідки).
- Наприкінці етапу: фінальний коміт трекера, оновлення пам'яті мовчки.
