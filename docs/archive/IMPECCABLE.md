# Шпаргалка по командам impeccable

`impeccable` — скіл для дизайну/редизайну/поліровки фронтенд-інтерфейсів. Працює з реальним кодом і дивиться на результат через живий dev-сервер + скріншоти браузера, а не на статику.

Виклик: `/impeccable <команда> [ціль]` (або `/impeccable` без аргументів → контекстне меню «що робити далі»).

---

## Шпаргалка команд

### Build — створити / налаштувати

| Команда | Що робить | Коли |
|---|---|---|
| `init` | Розгортає контекст проєкту: PRODUCT.md, DESIGN.md, конфіг, наступні кроки | Перший запуск у проєкті, де ще нема PRODUCT.md. Запускається автоматично як блокер, якщо контексту нема |
| `document` | Генерує DESIGN.md з наявного коду | Код є, дизайн-система не задокументована |
| `shape [feature]` | Планує UX/UI **до** написання коду | Нова фіча — спершу подумати, потім кодити |
| `craft [feature]` | `shape` + одразу будує фічу end-to-end | Нова фіча під ключ |
| `extract [target]` | Витягує повторювані токени/компоненти в дизайн-систему | Накопичилися дублі — час уніфікувати |

### Evaluate — оцінити (нічого не змінює)

| Команда | Що робить | Коли |
|---|---|---|
| `critique [target]` | UX-рев'ю з евристичним скорингом, лишає снапшот | Зрозуміти, що не так, отримати беклог проблем |
| `audit [target]` | Технічні перевірки: a11y, перформанс, адаптивність | Перед релізом перевірити WCAG / контраст / mobile |

### Refine — довести до пуття

| Команда | Що робить | Коли |
|---|---|---|
| `polish [target]` | Фінальний прохід якості (читає снапшот з `critique` як беклог) | Останній мазок перед шипом |
| `bolder [target]` | Підсилює прісний/безпечний дизайн | «Занадто нудно/безлико» |
| `quieter [target]` | Приглушує агресивний/перевантажений дизайн | «Занадто крикливо/строкато» |
| `distill [target]` | Зрізає зайве до суті | «Забагато всього, спрости» |
| `harden [target]` | Production-ready: помилки, i18n, edge-cases | Допиляти стани помилок / порожні стани / краї |
| `onboard [target]` | First-run флоу, порожні стани, активація | Новий користувач бачить порожній екран |

### Enhance — підсилити окрему вісь

| Команда | Що робить | Коли |
|---|---|---|
| `animate [target]` | Доречні анімації / рух | Інтерфейс статичний, бракує життя |
| `colorize [target]` | Стратегічний колір у монохром | «Кольори пласкі/сірі» |
| `typeset [target]` | Типографіка: ієрархія, шрифти | Заголовки/текст невиразні |
| `layout [target]` | Відступи, ритм, візуальна ієрархія | «Поправ spacing/вирівнювання» |
| `delight [target]` | Особистість, запам'ятовувані деталі | Додати характеру |
| `overdrive [target]` | Виходить за звичні межі | Потрібен «вау», амбітні ефекти |

### Fix — точкові правки

| Команда | Що робить | Коли |
|---|---|---|
| `clarify [target]` | UX-копірайт: лейбли, тексти помилок | Незрозумілі написи/повідомлення |
| `adapt [target]` | Адаптація під пристрої/розміри екрана | Ламається на mobile/tablet |
| `optimize [target]` | Діагностика і фікс перформансу UI | Гальмує, лагає |

### Iterate — ітерувати наживо

| Команда | Що робить | Коли |
|---|---|---|
| `live` | Тицяєш елемент у браузері → генеруються варіанти | Потрібен запущений dev-сервер; візуальний підбір на льоту |

### Management

- `pin <command>` — робить `/<command>` ярликом до `/impeccable <command>`.
- `unpin <command>` — прибирає ярлик.
- `hooks <on|off|status|...>` — авто-детектор слопу після правок UI-файлів.

## Послідовність запуску

Логіка проста: **спершу оцінити → потім підсилити окремі осі → наприкінці відполірувати**. Не починати з `polish`, поки не знаєш, що саме болить.

**Новий проєкт (з нуля):**
```
init → shape → craft → audit → polish
```

**Існуючий проєкт без дизайн-доків:**
```
document → critique → (enhance/refine за знахідками) → audit → polish
```

**Покращити наявний екран (типовий цикл):**
```
critique <екран>        # що не так + беклог
   ↓
colorize / typeset / layout / animate / clarify ...   # точкові осі за знахідками
   ↓
audit <екран>           # a11y / контраст / mobile
   ↓
polish <екран>          # фінальний прохід (читає снапшот critique)
```

**Просто «зроби краще», не знаєш з чого почати:**
```
/impeccable             # без аргументів → контекстне меню рекомендує 2-3 наступні кроки
```

### Орієнтири
- `critique` лишає снапшот, який `polish` потім читає як беклог → запускай `critique` **перед** `polish`.
- Enhance-команди (`colorize`/`typeset`/`layout`/`animate`/`delight`) — одна вісь за раз, точково.
- `bolder` ↔ `quieter` — протилежні регулятори гучності; обери один напрям.
- `live` потребує запущеного dev-сервера (`npm run dev`).
- Evaluate-команди (`critique`, `audit`) нічого не змінюють — безпечно ганяти будь-коли.
