# CONTRIBUTING — правило синхронізації документації

Документація тут — **стан, не журнал** (історія живе в `git log`). Щоб docs не дрейфували від коду,
діє одне жорстке правило.

## Залізне правило

> **Будь-яка зміна, що торкається RPC, схеми БД, RLS, грантів або ролей, ЗОБОВ'ЯЗАНА оновити
> відповідний розділ живого документа в ТОМУ Ж коміті.** Окремий «коміт документації потім» — заборонено.

Канон бізнес-логіки й інваріантів — кореневий `CLAUDE.md`. Живі документи в `docs/` — тонкі указівники
(куди дивитись + інваріанти), вони НЕ дублюють `CLAUDE.md`, а посилаються на нього. Тож зазвичай
оновлюється `CLAUDE.md` + (за потреби) указівник у `docs/`.

## Тип зміни → що оновити (у тому ж коміті)

| Зміна в міграції / коді | Оновити |
|---|---|
| Новий / змінений RPC (сигнатура, поведінка, гейт) | `CLAUDE.md` §RPC · [DATABASE.md](DATABASE.md) (якщо змінився канон/перелік) · [SECURITY.md](SECURITY.md) (якщо гейт/EXECUTE) |
| Нова / змінена таблиця, колонка, неочевидний бізнес-сенс | `CLAUDE.md` §Схема БД · `npm run sync:schema` (регенерує `types/database.types.ts`) |
| RLS-політика (нова/змінена/видалена) | `CLAUDE.md` інв. #9 · [SECURITY.md](SECURITY.md) · матриця в [ROLES_PLAN.md](ROLES_PLAN.md) §Фаза 3 |
| GRANT / REVOKE (роль ↔ таблиця/RPC) | [SECURITY.md](SECURITY.md) (розділ Гранти / привілейовані RPC) |
| Нова роль / зміна `auth_role()` / middleware-маршрутизації | [SECURITY.md](SECURITY.md) · [ROLES_PLAN.md](ROLES_PLAN.md) · `CLAUDE.md` §Карта коду (Роль) |
| Новий тригер | `CLAUDE.md` (де згадано пов'язаний RPC) · [DATABASE.md](DATABASE.md) |
| Нова вісь централізації (хук/хелпер/queries-модуль) | `CLAUDE.md` §Карта коду · [ARCHITECTURE.md](ARCHITECTURE.md) |
| Зміна CSS-системи / layout / модалок / mobile | [FRONTEND.md](FRONTEND.md) |
| Помітна архітектурна/схемна/безпекова віха | додати рядок у [CHANGELOG.md](CHANGELOG.md) (лише помітне, не кожен коміт) |

## Чого НЕ робити

- **Не плодити `.md` у корені.** Корінь — лише `CLAUDE.md` (канон) і `README.md` (вхід). Усе інше → `docs/`.
- **Не писати дати/«фази»/«видалено раніше» у живі документи** (інваріант #11). Це стан — історія в `git log`.
- **Не редагувати `docs/archive/**`** — заморожені звіти. Якщо знахідка застаріла, це покаже
  чек дрейфу; виправляється живий документ, не звіт.
- **Не переписувати `docs/legacy/**`** — старе робоче. Помічене `⚠️ LEGACY`; якщо поведінки більше
  немає — фіксуємо в живому документі, легасі лишаємо як є.
- **Не дублювати `CLAUDE.md` у `docs/`** — указівники тонкі; дублювання = неминучий дрейф.

## Legacy vs Archive (різниця)

- **`docs/archive/`** — разовий звіт із датою (аудит, регресія). Факт зафіксовано в момент часу,
  заморожено назавжди.
- **`docs/legacy/`** — робочий документ, що описує старе-але-можливо-живе поведінку або вже
  впроваджений план. Лишаємо й помічаємо, бо легасі може ще працювати (принцип: старе рабоче легасі
  не переписуємо, а помічаємо).

## Періодична звірка

Раз на N тижнів (або перед великим релізом) — прогнати [DRIFT_CHECK_PROMPT.md](DRIFT_CHECK_PROMPT.md):
він звіряє живі документи з реальним кодом/схемою/прод-RLS і видає список розходжень.
